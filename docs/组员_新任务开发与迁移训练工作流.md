# 组员工作流：用平地基础策略训练自己的新任务

适用项目：train/rc_mjlab` 的 `pointleg` 点足机器人。  
整理日期：2026-10-22。本文讲新任务开发和训练；环境安装、基础概念等细节见同目录的《组员_平地基础策略迁移训练工作流.md》。

## 要做的事情

每位组员领取一份已经会平地行走的 `model_0.pt`，在自己的代码分支或副本中，完成负责地形的环境、命令、奖励、课程和验收，再从该模型开始训练。

这不是把平地模型换个名字就能完成新任务，也不是要求大家继续优化平地奖励。基础策略负责提供起点，新任务代码决定接下来学什么。

新版基础文件位于 `pretrained/flat_9000_transfer/model_0.pt`：来自平地 9000 轮，训练轮次和公共环境步数均为 0，网络和优化器状态保留。组员不需要再清零这些计数。

主流程：

```text
明确任务与验收 → 搭建容易的地形 → 设计命令、奖励和失败条件
→ 注册任务 → 检查场景 → 在新场景回放基础策略 → 加载基础模型小规模训练
→ 分阶段增加难度 → 固定条件测试 → 选择最佳检查点 → 交付代码和模型
```

## 一、基本语法与常用命令

基本语法：

```text
pointleg train <TASK_ID> [OPTIONS]
pointleg play <TASK_ID> [OPTIONS]
```

使用项目已有环境时，在前面加 `uv run --locked --no-sync`。完整形式如下：

```text
uv run --locked --no-sync pointleg train <TASK_ID> [OPTIONS]
uv run --locked --no-sync pointleg play <TASK_ID> [OPTIONS]
```

下面以已启用的 `PointLeg-Rough-v0` 为例，日志目录是 `pointleg_rough`。如果训练其他任务，同时替换任务 ID 和对应日志目录；任务必须先实现并注册。`时间戳`、`model_xxx.pt` 是需要替换的内容，不是原样输入。

### 进入项目目录

```powershell
cd "E:\OneDrive\Desktop\RC_WheelLeg-main\05_software\train\rc_mjlab"
```

路径换成自己电脑的项目路径。统一在根目录执行，保证使用项目环境、锁文件和正确的相对路径。不是所有其他目录都会重新创建环境，但在无关目录执行可能找错项目。`--no-sync` 不负责首次安装环境。

### 正式训练

普通从零训练命令，仅作语法参考：

```powershell
uv run --locked --no-sync pointleg train PointLeg-Rough-v0 --env.scene.num-envs 512 --agent.max-iterations 1000 --agent.logger tensorboard --agent.upload-model False
```

本组要从平地基础策略开始，完成后文的基础文件放置后，使用这一条，而不是上面的从零训练命令：

```powershell
uv run --locked --no-sync pointleg train PointLeg-Rough-v0 --env.scene.num-envs 512 --agent.resume True --agent.load-run "flat_pretrained" --agent.load-checkpoint "model_0.pt" --agent.max-iterations 1000 --agent.logger tensorboard --agent.upload-model False
```

先用 512 个环境试运行；占用过高就降到 256 或更少。此前一台电脑在 512 环境时观察到约 80% 的内存占用，这不是所有电脑或地形的固定值。不要不看资源占用就直接使用 2048。

### 崩溃或主动停止后继续训练

把 `时间戳` 换成上一次实际输出的目录名，把模型名换成选中的检查点：

```powershell
uv run --locked --no-sync pointleg train PointLeg-Rough-v0 --env.scene.num-envs 512 --agent.resume True --agent.load-run "时间戳" --agent.load-checkpoint "model_xxx.pt" --agent.max-iterations 1000 --agent.logger tensorboard --agent.upload-model False
```

`--agent.max-iterations 1000` 是本次再训练 1000 轮，不是累计训练到第 1000 轮。若目标是补完原计划，需要自己计算还要追加多少轮。目录名若带有 `_stage1` 等后缀，`load-run` 也要写完整。

### 回放训练结果

本地原生窗口：

```powershell
uv run --locked --no-sync pointleg play PointLeg-Rough-v0 --checkpoint-file ".\logs\rsl_rl\pointleg_rough\时间戳\model_xxx.pt" --num-envs 4 --viewer native
```

浏览器 Viser 界面：

```powershell
uv run --locked --no-sync pointleg play PointLeg-Rough-v0 --checkpoint-file ".\logs\rsl_rl\pointleg_rough\时间戳\model_xxx.pt" --num-envs 4 --viewer viser
```

只看一个机器人时，把 `--num-envs 4` 改成 `--num-envs 1`。浏览器方式不代表已自动允许其他电脑访问；远程连接还需要单独处理地址、端口转发和网络权限。

自动获取某一次训练目录中最近保存的 `.pt`：

```powershell
$ckpt = Get-ChildItem ".\logs\rsl_rl\pointleg_rough\时间戳" -File -Filter "model_*.pt" | Sort-Object LastWriteTime -Descending | Select-Object -First 1 -ExpandProperty FullName
uv run --locked --no-sync pointleg play PointLeg-Rough-v0 --checkpoint-file $ckpt --num-envs 1 --viewer viser
```

先指定正确的训练目录，避免在整个日志树里误选基础模型或其他实验。这里选的是最近保存的文件，不保证是表现最好的模型。

不加载权重，只检查零动作下的初始姿态和场景：

```powershell
uv run --locked --no-sync pointleg play PointLeg-Rough-v0 --agent zero --num-envs 1 --viewer native
```

### TensorBoard 查看曲线

只看某次训练：

```powershell
uv run --locked --no-sync python -m tensorboard.main --logdir ".\logs\rsl_rl\pointleg_rough\时间戳"
```

同时查看、对比该任务的多次训练：

```powershell
uv run --locked --no-sync python -m tensorboard.main --logdir ".\logs\rsl_rl\pointleg_rough"
```

在浏览器打开终端提示的地址，通常是 `http://localhost:6006`。TensorBoard 读取的是训练事件日志，不是把多个 `.pt` 文件转换成曲线。

以上是命令速查。接下来按新任务开发流程完成环境和基础模型放置，再运行迁移训练命令；不会因为命令能执行就自动具备新的地形与奖励。

## 分工与边界

建议分别从同一个平地基础开始，输出自己的模型。不要让一个人训练完再覆盖基础文件交给另一个人，否则无法区分不同任务的影响。

## 阶段一：先写清楚“训练成功”是什么

动手前写一张任务卡

| 项目 | 要回答的问题 |
|---|---|
| 目标 | 从哪里出发，到哪里结束，需要完成什么动作？ |
| 地形 | 实际尺寸、可行走区域、障碍和碰撞体是什么？ |
| 出生 | 初始位置和朝向在哪里，是否在可靠支撑面上？ |
| 命令 | 机器人接收什么速度、方向或阶段指令？谁生成？ |
| 感知 | 策略凭什么知道需要爬坡、对齐或避开桥边？ |
| 成功 | 怎样判断真正完成，而不是停在原地或半途重置？ |
| 失败 | 跌倒、掉桥、非法接触、越界、超时分别怎样处理？ |
| 课程 | 最容易的版本是什么，以什么条件升级难度？ |
| 验收 | 用哪些场景、方向、速度和种子，重复多少次？ |

成功率必须有明确分母，例如成功通行次数除以总尝试次数。超时是成功还是失败由任务定义，不要默认“没有摔倒”等于成功。

阶段完成标志：组员能明确解释自己的模型最终要学会什么，且能用程序判断成功和失败。
并且明确最后目标的任务趋向值

## 阶段二：开发独立任务，保留基础接口


### 去哪里改

以下位置均以 `rc_mjlab` 为根目录：

| 文件 | 新任务里的工作 |
|---|---|
| `src/pointleg/terrains/competition_terrains.py` | 创建需要的物理地形；已有原生地形可直接复用 |
| `src/pointleg/config/env_cfgs.py` | 在对应任务工厂中组合地形、出生、命令、奖励、课程、终止和回放配置 |
| `src/pointleg/mdp/rewards.py` | 实现自定义奖励，并由环境工厂绑定和设权重 |
| `src/pointleg/mdp/commands.py` | 需要时实现目标任务的命令采样或更新逻辑 |
| `src/pointleg/mdp/terminations.py` | 需要时实现掉桥、越界等失败判定 |
| `src/pointleg/mdp/curriculums.py` | 需要时实现课程；核对实际调用的函数 |
| `src/pointleg/config/rl_cfg.py` | 配置独立实验名；第一版先保持兼容的网络结构 |
| `src/pointleg/__init__.py` | 完成任务工厂后，再注册／启用对应任务 |

优先在目标任务的配置工厂里覆盖设置，避免直接改公共基础函数影响其他组员。不要从包含全部优化奖励的 Flat 环境盲目继承：新任务的奖励应主动选择，不是默认全部保留。

### 第一版保持兼容，先不要随意改网络

当前基础模型的接口：

- Actor 输入 45 维：角速度 3、重力投影 3、速度命令 3、相对关节位置 12、关节速度 12、上次动作 12。
- Critic 输入 325 维；标准加载同时恢复 Critic，不能只保证 Actor 兼容。
- 输出为 12 个关节的位置偏移动作；关节排列、默认角、缩放、滤波、单位和坐标系必须一致。
- 网络隐藏层为 512、256、128，ELU；观测的顺序和含义也必须相同。

修改地形、奖励和命令采样范围一般不要求改变这些接口。若增加 Actor 高度图、目标点或其他输入，或改变 Critic 输入，需要单独设计权重迁移，不能继续按完整检查点直接加载。

桥梁任务尤其要明确感知方案：当前只有 Critic 使用高度扫描，Actor 没有地形扫描输入。不能因为仿真有传感器就假定策略能识别桥边。可以先由独立路线／命令生成逻辑引导低层行走，也可以设计额外观测；后者需要处理网络兼容。

阶段完成标志：任务能注册，场景和出生区域正确，观测／动作接口经过核对。

## 阶段三：奖励、指标和课程怎么安排

### 奖励分层，不先堆很多惩罚

| 类别 | 用途 | 示例思路，不是固定权重 |
|---|---|---|
| 主目标 | 引导真正完成新任务 | 有效前进、跟踪命令、到达合法出口 |
| 基础运动 | 保持可用控制 | 合理姿态、接触、动作平滑、能耗和滑移 |
| 任务约束 | 遵守场景规则 | 避免桥面越界、滑坡、非法碰撞 |
| 终止与成功 | 确认结果 | 明确失败重置、成功记录，必要时配套事件奖励 |

不要只奖励“靠近目标点”，否则可能抄近路；不要只惩罚危险，否则可能原地不动。桥梁需要判断是否沿合法区域完整通过；每步进展奖励还要避免通过来回移动重复刷分。

平地的绝对高度、强制水平姿态、固定落脚宽度、禁止腾空等约束可能与新任务冲突。根据任务重新检查，不需要复制组长的整套平地奖励，也不应假定旧版奖励一定适合新地形。

### 每个方向先从容易版本开始
如：

| 方向 | 第一阶段 | 中间阶段 | 最终验证 |
|---|---|---|---|
| 粗糙地形 | 平地与轻微起伏，较低速度 | 增大起伏和障碍组合 | 未见过的地形种子、不同速度和方向 |
| 坡地 | 缓坡，上下坡分别练 | 增加坡度、调整方向，加入坡顶坡底过渡 | 不同坡度、上下坡、停走切换 |
| 单边桥 | 可通行的宽桥、入口对齐、低速度 | 逐步收窄，加入入口位置和朝向变化 | 完整进桥、过桥、出桥及不同初始条件 |

这里的课程需要负责人实际写进配置／逻辑，不会因为文档这样写就自动发生。升级依据可以是通过率或能力指标；固定步数升级也要检查是否超过当前能力。桥宽不能脱离机器人实际支撑几何无限收窄。

先在少量环境中验证单项奖励是否随预期行为增减，检查单位、正负号、命令门控和边界。成功率、进度、掉桥等指标要单独记录，不能全靠总奖励间接猜。

阶段完成标志：能够解释每项关键奖励的目的，并检查过“站着不动、原地乱动、来回刷分”是否能得到不合理收益。

## 阶段四：检查场景，然后接入基础模型

以下都是 Windows PowerShell 命令。先进入自己的 `rc_mjlab` 根目录；已安装环境时使用 `--no-sync`。

### 设置自己负责的任务

下面默认用当前已启用的 Rough 演示。若换任务，必须同时修改任务 ID 和实验名；Bridge／Elevation 须先完成实现。

```powershell
$taskId = "PointLeg-Rough-v0"
$experimentName = "pointleg_rough"
$baseCheckpoint = ".\pretrained\flat_9000_transfer\model_0.pt"
uv run --locked --no-sync pointleg list
```

组员把收到的新版基础文件放到 `$baseCheckpoint` 对应位置。任务 ID、实验名、文件路径是三个不同概念，不要混用。后续使用这些变量的命令在同一个 PowerShell 窗口执行；新开窗口需要重新进入项目目录并设置变量。

### 先看场景，不训练

```powershell
uv run --locked --no-sync pointleg play $taskId --agent zero --num-envs 1 --viewer native
```

这会使用零动作检查场景，不是已经学会新任务。检查出生点是否悬空／穿模，桥和坡是否有真实碰撞，接触是否落在预期表面，重置和失败判定是否正确。零动作在困难地形失败不等于基础策略不可用。

### 在新任务中回放平地基础，记录训练前基线

```powershell
uv run --locked --no-sync pointleg play $taskId --checkpoint-file $baseCheckpoint --num-envs 1 --viewer viser
```

这一步不更新权重，只看“平地基础直接放到新地形上”能做到什么。记录成功／失败和主要问题，后面才能判断迁移训练是否真的带来改善。默认回放的扰动配置与训练可能不同，正式评估要统一测试条件。

### 放到新任务的加载目录

当前训练入口从目标任务的实验目录查找 `load-run`，不会自动去平地日志找文件。对新版双计数清零模型只需复制，不需要再运行清零代码：

```powershell
$targetBaseDirectory = Join-Path ".\logs\rsl_rl" "$experimentName\flat_pretrained"
New-Item -ItemType Directory -Path $targetBaseDirectory -Force | Out-Null
$targetBaseCheckpoint = Join-Path $targetBaseDirectory "model_0.pt"
if (Test-Path -LiteralPath $targetBaseCheckpoint) {
    throw "目标基础文件已存在。先确认版本，不要覆盖。"
}
Copy-Item -LiteralPath $baseCheckpoint -Destination $targetBaseCheckpoint -ErrorAction Stop
Get-FileHash -LiteralPath $baseCheckpoint -Algorithm SHA256
Get-FileHash -LiteralPath $targetBaseCheckpoint -Algorithm SHA256
```

两个哈希应一致。每个独立新任务各自准备一份基础文件；保留原件，不用训练结果覆盖。

## 阶段五：运行检查与第一段训练

### 小规模检查

```powershell
uv run --locked --no-sync pointleg train $taskId --env.scene.num-envs 16 --agent.resume True --agent.load-run "flat_pretrained" --agent.load-checkpoint "model_0.pt" --agent.max-iterations 2 --agent.run-name "smoke_from_flat" --agent.logger tensorboard --agent.upload-model False
```

只检查能否加载、运行和保存，不判断步态。终端必须显示实际加载了目标实验下的 `flat_pretrained/model_0.pt`。如果有维度错误、NaN、初始化异常或出生后反复立即重置，先修复，不开始大规模训练。

### 第一段正式迁移训练

```powershell
uv run --locked --no-sync pointleg train $taskId --env.scene.num-envs 512 --agent.resume True --agent.load-run "flat_pretrained" --agent.load-checkpoint "model_0.pt" --agent.max-iterations 1000 --agent.run-name "stage1_from_flat" --agent.logger tensorboard --agent.upload-model False
```

1000 轮只是首段观察窗口，不保证学会任务。显存不足可以降低环境数量。正式训练仍从保留的平地基础开始，不必接着小检查的两轮训练。

当前命令恢复 Actor、Critic、优化器和轮次。新奖励会改变价值估计，初期波动不代表必然失败；如果持续退化，应检查任务和课程，再由负责人评估是否需要只迁移 Actor、重置 Critic／优化器。不要直接删模型字段试错。

从 0 执行 1000 次迭代，当前实现最终通常是 `model_999.pt`。`max-iterations` 是本次追加轮数，不是累计终点。输出位于 `logs/rsl_rl/<实验名>/<时间戳>_stage1_from_flat`，基础文件不被覆盖。

## 阶段六：看问题，调整一个方面，再训练

### 看曲线

另开终端，进入同一项目根目录：

```powershell
uv run --locked --no-sync python -m tensorboard.main --logdir ".\logs\rsl_rl" --port 6006
```

浏览器访问 `http://localhost:6006`。重点看自己的成功率、任务进度、失败原因和速度跟踪，再看平滑度、滑移和代价；不同奖励版本的总分不能直接比较。

### 回放具体检查点

回到设置过 `$taskId` 和 `$experimentName` 的窗口，把下面两个值替换为实际输出：

```powershell
$runName = "<本次实际输出目录名>"
$checkpointName = "model_999.pt"
$trainedCheckpoint = Join-Path ".\logs\rsl_rl" "$experimentName\$runName\$checkpointName"
uv run --locked --no-sync pointleg play $taskId --checkpoint-file $trainedCheckpoint --num-envs 1 --viewer viser
```

必须在目标任务回放，不能只在平地看起来顺畅就宣布复杂地形训练成功。

| 看到的问题 | 优先排查，再决定怎么调 |
|---|---|
| 出生就失败 | 几何、出生点、初始姿态、终止条件 |
| 完全不愿运动 | 命令是否有效、进展奖励是否足够、运动代价是否压过收益 |
| 乱冲／绕开障碍也得分 | 路线和成功条件是否允许投机 |
| 一增加难度就大面积失败 | 课程升级是否太快、初始难度是否过高 |
| 过了障碍但步态退化 | 动作、滑移和接触指标；必要时混入简单地形回测 |
| 速度正确但经常掉桥 | 桥面落脚／边界信息、姿态、引导与失败检测 |
| 总分升高但通过率不升 | 奖励目标和真实任务是否一致 |

一次优先调整一个方面，例如先修命令、再修地形课程、再调整奖励。每次记录改了什么、新旧测试结果如何。不要同时改网络、PD、地形、命令和所有权重。

同一个任务继续训练时，从该任务选中的检查点加载，不再返回平地基础，也不要重复清零课程：

```powershell
uv run --locked --no-sync pointleg train $taskId --env.scene.num-envs 512 --agent.resume True --agent.load-run $runName --agent.load-checkpoint $checkpointName --agent.max-iterations 1000 --agent.run-name "stage2" --agent.logger tensorboard --agent.upload-model False
```

若某次修改导致持续退化，可以回退到该任务较好的检查点重新开一个分支实验；改变目标为另一个独立任务时，再从平地基础建立新实验。

## 阶段七：验收与交付

不要仅凭曲线饱和或一段好看的 Viser 动画验收。提前固定测试场景和命令，对多个检查点使用相同条件重复测试；训练内场景和未见过的测试场景分别统计。

| 方向 | 至少需要分别验证 |
|---|---|
| 粗糙地形 | 不同地形种子、难度和指令下的通过率、跌倒和跟踪 |
| 坡地 | 上坡、下坡、过渡区域，以及停走或方向变化 |
| 单边桥 | 入口对齐、桥上通行、合法出桥；不同初始偏差和掉桥次数 |
| 所有方向 | 平地基本行走是否严重退化，是否出现长期单腿不落地等异常 |

测试次数和合格阈值先由任务负责人和组内确定，固定后再比较，不能看到结果以后临时更改标准。完整通行率比“平均活得久”更接近桥梁任务目标。关闭终止条件后的录像不作为成功证明。

交付内容：

- 最佳检查点和准确任务 ID，而不是只交最后一个 `.pt`。
- 对应代码版本，以及自定义地形、奖励、命令、终止和课程实现。
- 当次 `params/env.yaml`、`params/agent.yaml`，以及复现命令。
- 测试条件、尝试次数、通过率、主要失败原因和演示录像。
- 明确说明仍未通过的情况和模型接口；仿真结果不能直接作为宇树电机实机安全依据。

最终交付的是“可复现的新任务训练成果”，不只是改过名字的平地权重。
