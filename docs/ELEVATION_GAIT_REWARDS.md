## 2026-10-30承重后扫、换步与近距离出生（版本6，历史）

用户回放版本5在400轮附近仍有退化，并要求支撑期更充分、前足不过度前伸、前后腿姿态更接近及缩短接近障碍前的平地。版本6保留15厘米净空、0.15～0.25米/秒、60秒时限和固定120毫米台阶，补充承重推进质量与换步约束；不是给脚在地上向后滑动加分，也不强制前后腿在每一帧同角度。

### 支撑与迈步

真实承重沿用顶面法向、有限力且每足至少8N的判定。支撑足世界位置稳定、身体向前移动时，足端相对机身后移是有效后扫；稳态闭合步态中，同一坐标系的前后位移需要闭合，不要求后扫净位移无限大于前摆。

| 项目 | 版本5 | 版本6 |
|---|---|---|
| 短触地代价 | 最短0.08秒、权重−0.02 | 最短0.16秒、权重−0.05 |
| 循环落地确认 | 连续0.06秒承重 | 连续0.10秒承重 |
| 支撑推进质量 | 未单独评价 | 至少0.16秒支撑才取得该质量，0.35秒/7厘米有效后扫饱和 |
| 循环质量系数 | 高度×收腿×步长 | 原质量再乘`0.25+0.75*支撑推进质量` |
| 单足长时间不换脚 | 仅循环参与度 | 增加`stance_overstay`−0.3，连续承重超过0.85秒起扣，1.10秒归一化饱和 |
| 速度收益 | 新前沿推进且至少两足支撑 | 还需最近有真实循环；不再允许固定四足只靠身体前探持续领速度收益 |

支撑推进质量=`clip(支撑时长/0.35)*clip(有效后扫/0.07)*clip(1-支撑足最大切向漂移/0.025)`，各clip均在0～1。有效后扫取“身体沿起脚支撑面切线的推进”和“身体相对足端的切向推进”较小值并截去负数，防止靠脚向后滑动放大信用。支撑漂移保留最大值，滑出去又滑回来不能洗掉；它是球足中心位移的几何近似，2.5厘米为训练容差，真实接触点滑移代价继续保留。纯垂直起伏、短触地或只摆膝不能单独取得高推进质量。支撑期身体世界Z升高只记录指标，不直接奖励用大力垂直弹跳。

推进质量在离地时冻结，随后仍须完成真实抬脚、前向落足和稳定承重，才结算原循环奖金；没有额外独立支付支撑奖金。保留25%基础质量反馈，让尚未学好后扫的有效小步仍有恢复机会。原每8厘米新机身进度满质量+0.08、单次最多+0.16的上限保持，但满质量现在包含有效支撑推进。

每足增加独立换步时钟：有效循环需离地/前进/落地条件成立，峰值至少当次目标20%（基础目标15厘米时为3厘米）、相对收腿质量至少40%才刷新；低于15厘米仍有连续高度反馈，不把12厘米做成所有收益的硬门槛。换步年龄0.6秒以内不衰减，0.6～1.2秒线性衰减，取四足平均与最差足各一半；四足都不换步1.2秒后，速度正奖励为零。支持慢一点的正常承重，也限制固定足端的身体前探。

## 目标与原因

训练目标是四条腿都参与的小步、足够净空、重新承重的行走，而不是前腿大幅前伸后拖着后腿通过。当前实现没有移植MIT控制器或硬编码足端轨迹，也没有新增相位输入或锁定对角步态；奖励是软引导，不保证未经训练就能得到指定动作风格。

旧实现的净空不足只在完成有效摆腿后结算，长期不抬脚的腿可能避开该项；旧前后伸腿容许范围也较宽，单纯推进和首次踩阶不能保证四条腿正常换步。本次分别加入四足独立的循环质量、参与度和短步幅反馈。

首次踩阶奖励只做事件去重，从来不代表同一台阶只能踩一次。现在，同一踏面内只要足端和机身都取得新前向进度，可以多次完成有质量的小步，并多次获得步态反馈；反复原地点脚、来回踩同一位置不符合条件。

## 每条腿的有效循环

循环为合法承重、离地、足够净空、向前落足、重新稳定承重。要获得循环奖励，需满足：

- 先有合法承重，离地至少0.08秒，摆动期间始终至少两足支撑。
- 同足取得至少3厘米新前向落点，机身取得至少2厘米新前向进度，且都超过该足此前已经结算的位置前沿。
- 落足后保持0.06秒承重，相邻结算至少间隔0.40秒，不在失败或无效状态发正奖励。
- 奖励同时考虑净空、实际收腿、不过长的步幅。相对起脚支撑面法向的收腿参考为2.5厘米；单纯抬高机身而不收腿不能当作优质循环。

每足单次实际奖励最多0.04，按机身新增进度相对8厘米比例缩放；每足单位时间奖励上限为0.1/秒。高度目标达成后饱和，不奖励越抬越高或越悬越久。四足分别记录，不强制每一级由哪只脚踩，也不要求每跨一级只迈一步。

四足分别维护距最近一次合格循环的时间。超过0.9秒开始扣参与度代价，1.8秒达到单足归一化上限；启动宽限0.6秒。合格循环需要高度和相对收腿质量达到80%，浅抬、点地或大步前伸不能清除该足计时。最差足与四足平均各占一半，不能靠两条前腿高频动作掩盖右后腿一直拖地。

## 坡面、俯仰和接触参考

- 工作区沿坡面切向计算，不设固定足端世界高度，也不把所有足端统一向世界负Z平移。坡上脚的世界高度可能增加，但相对机身和支撑面的姿态应随坡度变化。
- 坡面净空使用球足到坡面的法向距离，包含球半径修正；相对机身收腿使用起脚时支撑面的法向，避免坡脚、坡顶切换时参考突然改变。
- 身体俯仰参考优先拟合真实承重接触点的前后高度关系；接触跨度或数量不足时退回已知坡面参考。楼梯允许15度相对偏差、坡面10度、平地5度，不把上坡时的合理倾斜当作世界水平误差。
- 支撑滑移用真实接触点速度 `v_site + omega × (p_contact - p_site)`，再投影至接触切面。正常支撑脚相对机身向后运动不等于相对地面滑动；单足滑动也不能被其他三足平均掩盖。

平地8厘米目标是仿真初值；最高120毫米台阶对应局部立面约15厘米抬升目标。检查的是采样到的局部窗口与摆腿峰值，不是完整扫掠轨迹净空证明，真实碰撞、六阶覆盖和出口稳定判定仍保留。

## 何时才用权重迁移

只有跨任务、接口/地形/课程实际不兼容，或者用户主动希望重置优化器与课程时，才使用 `transfer`。回滚到较早、步态更正常的同任务检查点也可以直接 `resume`，不需要自动重置进度。

```powershell
.\.venv\Scripts\python.exe -m pointleg.run transfer PointLeg-Elevation-v0 --checkpoint-file "源模型路径/model_xxx.pt" --output-run fresh_training_state
```

代码不会热更新既有训练进程。修改奖励也不会在旧模型回放时强制更换动作；必须重新训练并检查四足循环、滑移、实际净空和分地形通过率。
