当前Stairs成功规则（revision 15）：上台阶必须六级踏面都至少有一次有效足端承重接触，再由四足同时在最高出口平台真实承重完成；下台阶也必须覆盖六级踏面，再由四足在最低出口平台真实承重完成，避免下行从最高出生平台立即成功。每足出口接触必须在局部`x>=exit_x`、通道内、高度匹配目标平台（容差8毫米）、法向朝地且法向承重至少8N。掉到800毫米通道之外立即失败。上阶摆动抬升不足120毫米不再触发失败，原指标仅作诊断且存在起脚采样偏差，不保证120毫米硬要求。

坡面任务的重置采样始终只含`slope_up`和`slope_down`，256环境时各128个；局部重置保持同一方向分配。物理4×4大地图仍保留旧楼梯等地块，但不在这些地块中分配Slope回合。已核对旧运行`2026-11-01_20-17-27_train_2/params/env.yaml`的两个重置事件均为`terrain_kind: slope`；该旧运行参数仍为0.15～0.25米/秒、60秒，不代表已经采用本文最新设置。

当前Slope成功规则：上坡四足同时在坡尾顶部平台承重，下坡四足同时在坡尾底部平台承重，当步结算`task_completed=+20`并由训练环境自动重置。每足至少一个真实接触点位于局部`x>=exit_x`、通道内且高度匹配出口平台（容差8毫米），接触法向朝地面，法向承重至少8N。三足到达、一足仍在坡上、无承重、侧面碰撞或下坡刚出生于顶部平台都不算成功；已发生出界、摔倒等失败时不能同时领取成功。取消Slope原有整机后缘越过坡尾10厘米以及额外稳定0.5秒要求。

增加`Metrics/slope_up_fraction`、`Metrics/slope_down_fraction`和`Metrics/slope_exit_loaded_feet`，分别核对实际任务分配和出口平台承重足数。成功先进入终止标志，再按控制周期补偿结算单次+20，随后框架重置；固定评估的`auto_reset=False`模式由评估器收集结果。旧Slope检查点可以同任务resume，会提示奖励/成功契约变化，保存元数据记录四足出口承重及零额外等待时间。

## 基础奖励白名单

| 项目 | 权重 | 含义 |
| --- | --- | --- |
| `velocity` | +2 | 参考HighStep，按实际前向速度与指令速度计算；静止和后退为0，失败、完成和无效状态为0，不联乘步态质量或路程额度 |
| `task_completed` | +20 | 完成后的单次事件 |
| `task_failed` | −50 | 掉出通道、摔倒、停滞、越限、非法状态或超时等失败事件 |
| `lateral` | −3 | 机身横向速度超过0.010米/秒后，按0.10米/秒尺度平方扣分，左右等价 |
| `yaw_rate` | −0.5 | 偏航角速度超过2度/秒，按20度/秒尺度扣分 |
| `edge` | −1 | 承重足靠近800毫米通道边缘 |
| `slip` | −1 | 真实接触点切向滑移，均值与最差足各半 |
| `attitude` | −0.5 | 横滚和相对支撑面俯仰偏差，允许随上/下坡改变机身倾角 |
| `angular` | −0.1 | 机身横滚及俯仰角速度过大 |
| `support_deficit` | −2 | 少于两足以至少8牛承重，排除侧面接触和非有限接触数据 |
| `joint` | −0.2 | 超出关节软限位 |
| `torque` | −0.02 | 归一化驱动力矩平方 |
| `action` | −0.02 | 相邻控制周期动作突变 |
| `contact_cost` | −0.2 | 非足端身体碰撞及足端侧向碰撞 |

速度评分为 `clip(vx/cmd,0,1) × exp(-((vx-cmd)/0.10)²)`，不和抬脚、承重时长、后扫距离相乘。奖励管理器对连续项乘控制周期；完成和失败使用现有事件接口补偿，单次分别为+20和−50，不能把事件权重和连续权重直接当成同一时长的总收益比较。

基础版曾去掉复合换步质量、固定足高、时序和慢姿态目标；当前Slope和Stairs都加入本文开头的周期/承重和慢姿态约束。Stairs要求六级踏面覆盖和四足出口承重；掉落和停滞判定仍生效。

旧复合模块的足高/循环质量指标从新任务中移除，避免访问已经移除的奖励状态；功能评估缺失的足高/缓冲数据报告为缺测，不应当作0高度或已达到指标。Stairs奖励元数据为版本15，Slope为版本11。Stairs的`stairs_clearance_failed`是旧阈值诊断指标，不再是终止原因。

## 初始化与续训

源策略为 `logs/rsl_rl/pointleg_high_step/2026-11-01_12-41-56_tran_4_2/model_14100.pt`。两个合并任务使用各自目录下的 `highstep_tran_4_2_14100_pretrained/model_0.pt`，迭代、优化器和课程从0开始。旧单方向任务的历史日志和检查点文件保留，但入口已经下线；若要使用旧权重，应对这三个现有任务之一执行纯权重transfer，不能直接完整resume到不同任务范围。

在 `rc_mjlab` 目录按需选择一条运行。台阶新任务建议从现有同任务初始迁移权重开始追加5000次更新、每100次保存：

```powershell
uv run --locked --no-sync pointleg train PointLeg-Slope-v0 --env.scene.num-envs 256 --agent.resume True --agent.load-run highstep_tran_4_2_14100_pretrained --agent.load-checkpoint model_0.pt --agent.max-iterations 200 --agent.save-interval 100 --agent.run-name basic_slope --agent.logger tensorboard --agent.upload-model False

uv run --locked --no-sync pointleg train PointLeg-Stairs-v0 --env.scene.num-envs 256 --agent.resume True --agent.load-run highstep_tran_4_2_14100_pretrained --agent.load-checkpoint model_0.pt --agent.max-iterations 5000 --agent.save-interval 100 --agent.run-name stairs_hardclearance_r12 --agent.logger tensorboard --agent.upload-model False
```

这次只实施配置/张量/检查点加载检查和初始化迁移，不自动启动仿真、Viser或训练。训练时分别看两个方向的失败原因、通过情况、侧漂和实际迈步；基础奖励没有保证足高保持在15厘米。

代码入口：`config/stairs.py`、`config/slope.py`、`config/elevation_basic.py`、`mdp/elevation_basic.py`。后续调整公共基础奖励会同时作用于这两个合并任务。
