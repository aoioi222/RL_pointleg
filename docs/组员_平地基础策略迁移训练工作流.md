# 组员操作指南：从平地基础策略开始训练复杂地形

适用项目：`05_software/train/rc_mjlab` 中的 `pointleg` 点足四足机器人。  
整理日期：2026-10-22。任务状态和命令依据整理时的本项目代码核对。

阅读顺序：负责开发粗糙地形、坡地或单边桥的组员，先读同目录的《组员_新任务开发与迁移训练工作流.md》；本文作为基础概念、模型接口和操作细节参考。新版模型已将两项计数清零，新任务主流程可以直接复制该文件，不必再次清零。

## 先看结论

提供的新版 `model_0.pt` 已经学过平地站立和行走。它来自平地的 `model_9000.pt`，内部训练轮次和环境累计控制步数均已改成 0，不是一个尚未训练的模型。

可以加载它，再用自己的地形、奖励和指标训练粗糙地形、上下坡或单边桥，不需要复现优化过的全部平地奖励。

前提是模型、观测、动作和网络接口兼容。修改奖励通常不影响加载；修改输入输出接口可能导致无法加载，或者能加载却控制异常。

整体流程：

```text
接收基础模型 → 核对接口 → 平地回放 → 开发目标任务
→ 准备迁移副本 → 小规模检查 → 分阶段训练 → 固定条件验收 → 保存最佳模型
```

## 基础概念

| 名称 | 在项目里负责什么 |
|---|---|
| 环境 | 机器人、地形、传感器、出生位置和仿真规则 |
| 观测 | 提供给网络的信息，如姿态、关节状态和速度命令 |
| 策略 Actor | 根据观测输出动作，即实际控制时主要使用的网络 |
| 价值网络 Critic | 在训练中评估状态，帮助更新策略 |
| 动作 | 当前策略输出的 12 个关节位置偏移控制量 |
| 奖励 | 训练时告诉算法哪些行为更符合目标 |
| 终止条件 | 判断摔倒、掉桥、超时等情况，结束并重置回合 |
| 课程学习 | 从容易的速度、地形或障碍开始，逐步增加难度 |
| 检查点 `.pt` | 保存网络参数、优化器状态、轮次及部分环境状态 |
| `play` | 加载策略进行仿真回放，不更新策略 |
| 续训／迁移训练 | 从已有模型继续更新，而不是重新初始化网络 |

`.pt` 不会自动携带地形、奖励函数或命令生成器的 Python 代码。它也不是可以直接发给电机执行的控制程序。

## 接口兼容检查：先不要随意改这些

### 网络输入

当前 Actor 的 45 维观测依次为：

| 顺序 | 内容 | 维数 | 说明 |
|---|---|---:|---|
| 前一组 | 机身角速度 | 3 | 当前配置缩放为 0.25 |
| 接着 | 机身坐标系重力投影 | 3 | 用于反映姿态 |
| 接着 | 速度命令 | 3 | 前后、左右和转向 |
| 接着 | 相对默认姿态的关节位置 | 12 | 不是任意定义的绝对电机角度 |
| 接着 | 关节速度 | 12 | 当前配置缩放为 0.05 |
| 最后一组 | 上一次动作 | 12 | 顺序必须与动作一致 |

Critic 还包含机身线速度、足端接触和高度扫描信息，总输入为 325 维。当前标准续训会同时加载 Actor、Critic 和优化器，不能只检查 Actor 是否兼容。

即使维度相同，交换观测顺序、改变坐标系、单位或缩放，也会改变网络看到的信息。

### 网络输出和执行

动作顺序为：左前 `fl`、右前 `fr`、左后 `rl`、右后 `rr`；每条腿内部为髋外展、髋俯仰、膝关节。

```text
12 个原始动作值
→ 延迟与低通滤波
→ 默认关节角 + 缩放后的动作
→ 关节角限位
→ 位置 PD 控制
→ 仿真关节力矩
```

当前默认站姿角为髋外展 0、髋俯仰 0.550、膝关节 -1.125，单位 rad。髋外展动作缩放为 0.125 rad，另外两类关节为 0.25 rad；不是在上一时刻角度上不断累加。

当前控制频率为 50 Hz；仿真默认 Kp=50、Kd=1.5，力矩限幅为 ±25 N·m。训练中还可能配置增益等随机化。默认站姿、动作缩放、滤波、关节轴向、机器人尺寸和动力学都不能无说明地更换。

这些是仿真参数，不是已验证的宇树电机实机参数。已确认实物是宇树仿生关节电机，而旧项目文档记录的是其他型号；不要把旧型号记录或仿真限幅直接当作实机依据。

## 第四步：为新任务准备迁移副本

### 为什么不是直接改任务名就训练

当前训练入口按以下结构寻找续训文件：

```text
logs/rsl_rl/<目标任务实验名>/<load-run>/<load-checkpoint>
```

例如 Rough 默认在 `pointleg_rough` 下找模型，不会自动去 `pointleg_flat` 下找。因此要把基础模型的迁移副本放入目标任务对应目录。

历史日志中的旧版 `model_0.pt` 虽然轮次为 0，但保留了 `common_step_counter=216168`；新版交付文件已经把它清零。当前 Rough 的部分地形解锁条件读取这个计数，误用旧版文件可能一开始就解锁后续障碍。下面的处理兼容两版文件：确认轮次和课程计数为 0，并放到目标任务的目录。

### Rough 示例：生成课程计数清零的副本

下面这段直接粘贴到 PowerShell 执行。它只生成新文件，不改变 `pretrained` 中的原件；目标文件已存在时会停止，避免覆盖。它不重置优化器，也不改变网络权重。

```powershell
$prepareTransfer = @'
from pathlib import Path
import torch

source = Path("pretrained/flat_9000/model_0.pt")
destination = Path("logs/rsl_rl/pointleg_rough/flat_pretrained/model_0.pt")
checkpoint = torch.load(source, map_location="cpu", weights_only=True)
checkpoint["iter"] = 0
infos = checkpoint.get("infos")
if not isinstance(infos, dict):
    infos = {}
env_state = infos.get("env_state")
if not isinstance(env_state, dict):
    env_state = {}
env_state["common_step_counter"] = 0
infos["env_state"] = env_state
checkpoint["infos"] = infos
destination.parent.mkdir(parents=True, exist_ok=True)
with destination.open("xb") as output:
    torch.save(checkpoint, output)
print("Created:", destination.resolve())
print("Iteration and curriculum counter are 0; network and optimizer state retained.")
'@
uv run --locked --no-sync python -c $prepareTransfer
```

这是“保留平地能力，重新开始新任务计数”，不是把网络清零。这里重置的只是已知的公共课程计数；自定义任务若另存了其他课程状态，需要任务负责人另外检查。

以后 Bridge 实现后，把副本放到该任务实际的实验目录，例如 `pointleg_bridge/flat_pretrained/model_0.pt`。不要把全部任务的日志混在一个实验名里。

## 第五步：先做小规模运行检查

以已经启用的 Rough 为例：

```powershell
uv run --locked --no-sync pointleg train PointLeg-Rough-v0 --env.scene.num-envs 16 --agent.resume True --agent.load-run "flat_pretrained" --agent.load-checkpoint "model_0.pt" --agent.max-iterations 2 --agent.run-name "rough_smoke" --agent.logger tensorboard --agent.upload-model False
```

检查终端是否明确输出加载了 `pointleg_rough/flat_pretrained/model_0.pt`，并确认场景能生成、模型能加载、训练能完成、输出没有 NaN 或形状错误。

2 轮只用于发现运行错误，不足以评价步态。正式训练仍从 `flat_pretrained/model_0.pt` 开始，不必从这次小检查的输出接着训练。

如果这里出现 `size mismatch`、缺少关键字段或输出维度不符，先停止并检查接口或依赖版本。不要删除不兼容层后就直接训练，也不要为了消除报错随意调整维度。

## 第六步：开始第一段迁移训练

先训练一段再检查，下面的 1000 轮是观察窗口，不是“训练成功所需轮数”：

```powershell
uv run --locked --no-sync pointleg train PointLeg-Rough-v0 --env.scene.num-envs 512 --agent.resume True --agent.load-run "flat_pretrained" --agent.load-checkpoint "model_0.pt" --agent.max-iterations 1000 --agent.run-name "rough_from_flat" --agent.logger tensorboard --agent.upload-model False
```

显存不足时可先降低环境数量。不要同时大改奖励、地形、网络和超参数，否则很难知道哪项变化导致结果。

注意：

- `--agent.resume True` 才会走当前项目的本地检查点加载流程；只放文件而不开启 resume，仍会重新初始化网络。
- `--agent.max-iterations 1000` 表示本次再执行 1000 次迭代，不是累计终点必须为 1000。
- 从内部 `iter=0` 执行 1000 次，当前实现最终通常保存为 `model_999.pt`；以实际输出文件为准。
- 当前标准加载会恢复 Actor、Critic、优化器和轮次。重置轮次不等于重置优化器；如果奖励差异很大而迁移效果差，可再由负责人评估是否只迁移 Actor、重置 Critic／优化器，不要新手直接删 checkpoint 字段。
- 输出会进入新时间戳目录，不覆盖 `flat_pretrained` 的基础文件。

默认日志结构示例：

```text
logs/rsl_rl/pointleg_rough/
├── flat_pretrained/
│   └── model_0.pt
└── <本次时间戳>_rough_from_flat/
    ├── params/
    │   ├── agent.yaml
    │   └── env.yaml
    ├── events.out.tfevents...
    └── model_999.pt
```

## 第八步：如何判断结果，而不是盲目增加轮数

优先判断是否真正完成目标，其次看过程质量，最后结合训练曲线。

| 层次 | 需要检查什么 |
|---|---|
| 任务结果 | 规定起点到终点的通过率、是否踩空或跌倒、完成耗时 |
| 控制效果 | 实际速度是否跟踪命令，是否只是站着或乱走以避免失败 |
| 步态质量 | 是否长期翘一条腿、明显偏腿、打滑、砸地或频繁跳起 |
| 泛化能力 | 不同出生位置、速度、方向、地形种子下是否重复成功 |
| 训练日志 | 相关奖励、误差、终止原因和课程难度是否合理 |

平地筛选可把零指令、前进、后退、侧移、转向和启停分别测试；初步每种情况运行 20 秒、重置后重复 5 次。这个数量只是方便比较，不是竞赛或实机合格标准。桥梁等任务更适合统计完整通行次数和通过率，而不是只看 20 秒内没摔倒。

比较两个模型时，尽量固定环境、初始条件、命令和随机种子，重复测试；不要拿一个模型的容易场景和另一个模型的困难场景对比。

曲线“饱和”只能说明当前训练中改善变少，也可能卡在不好的策略上。总奖励更高也不保证步态更自然；奖励项或任务不同，总分不能直接比较。保留多个检查点，按任务实测表现选最佳模型，不默认最后一个最好。

### 常见图的阅读方式

| 图或指标 | 如何理解 |
|---|---|
| `Train/mean_reward` | 同一奖励版本下辅助判断趋势，不是通行率 |
| `Train/mean_episode_length` | 越接近回合上限通常说明更少提前终止，但不代表完成目标 |
| `joint_torques` | 当前负权重力矩代价，越接近 0 代价越小；数值不是直接的 N·m |
| `body_collision`、`feet_slip` 等负惩罚 | 一般越接近 0 越好，前提是没有靠停止运动来逃避任务 |
| `foot_lateral_placement` | 若有该项，惩罚直行时前后足对中心向一侧偏移，不直接等于两脚间距 |
| `short_stance` | 若有该项，惩罚过短的支撑，不直接给出每条腿的支撑时长 |
| `Episode_Termination/*` | 当前记录是计数口径，不能直接把数值当百分比 |
| 自己新增的通过率／成功率 | 必须先明确成功条件及统计分母，区分真实通行与超时存活 |

`Episode_Reward` 还受回合长度和日志归一化方式影响，不能仅凭惩罚变负就直接断言真实力矩或碰撞频率按同样比例增加。必要时记录未加权的物理量。

## 第九步：继续训练与分工保存

如果结果还在改善、任务没有明显退化，可从本任务的检查点继续。下面两个占位内容必须替换为实际值：

```powershell
uv run --locked --no-sync pointleg train PointLeg-Rough-v0 --env.scene.num-envs 512 --agent.resume True --agent.load-run "<上一段实际目录名>" --agent.load-checkpoint "<选中的模型文件名.pt>" --agent.max-iterations 1000 --agent.run-name "rough_stage2" --agent.logger tensorboard --agent.upload-model False
```

这次是在同一个任务内继续，应保留已经学到的课程进度，不要每次都清零。新开一个任务时才按需要准备新的迁移副本。

分工建议：粗糙地形、坡地、桥梁分别从保留的平地基础启动，各自保存实验。不要在同一个输出目录轮流接着训练不同任务，也不要先覆盖平地基础再转交给下一个人。

训练难度逐步提高；可以根据任务设计混入部分平地，定期回测基础行走是否退化。这种迁移通常能减少从零探索，但不保证所有任务都更快，也不保证原步态永远保持不变。

## 常见问题速查

| 现象 | 优先检查 |
|---|---|
| 找不到检查点 | 当前任务的实验目录、`load-run` 和 `load-checkpoint` 是否一致 |
| 从头开始训练 | 是否加了 `--agent.resume True`，终端是否输出了实际加载路径 |
| 轮次是 0，难地形却立即解锁 | 是否还恢复了旧的 `common_step_counter` |
| `size mismatch` | Actor、Critic 输入和网络结构是否改变 |
| 能加载但腿方向或姿态异常 | 观测顺序、关节排列、正方向、默认角、单位和动作缩放 |
| 平地正常，新地形立刻失败 | 课程是否太难、出生点是否正确、奖励是否冲突、观测是否足够 |
| 不动但分数不低 | 是否缺少任务进展要求，运动代价是否过强，命令和完成条件是否正确 |
| 找不到 Bridge 或提示尚未实现 | 当前仍是占位任务，需要先实现并注册，不是模型文件的问题 |
| 训练奖励上升但通行率下降 | 是否利用了奖励漏洞，是否缺少真正的成功／失败判定 |
| 后退没学会 | 是否真的采样了负速度，是否实际跟踪了负速度，不能靠总平均指标判断 |
